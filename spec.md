

2. Functional and Non-Functional Requirements?
- Functional Requirements - Solution capabilities and behavior
- Non-Functional Requirements - Perfromance or quality characteristics


3. Primary SRS audience
- Tehcnical team
- Subject matter experts (SME)
- Testing Teams (QA, UAT, etc)


4. Main components of an SRS

- Introduction
    - Purpose: Describes the purpose of the SRS, Indentidies the product and the audience
    - Project Scope: Goals, Objectives and Expected Outcomes
- Overall Description
    - Product Perspective
    - User Classes 
    - Operating Environment
    - Constraints
    - Assumptions
    - Dependencies
- Business Rules
    - Rules
    - Description
    - Related Requirement
- Functional Requirements
    - Actor
    - Action
    - Object
    - Qualifier
- Use Cases
    - Use Case Diagram
    - Use Case Description
- Data Requirements
    - Data Model
    - Data Dictionary
    - Data Maintenance
- External Requirments
    - User Interfaces
    - Software Interface
    - Hardware Interface
    - Communication Interface
- Non-Functional Requirements
    - Availability
    - Compatibility
    - Performance
    - Portability
    - Reliability
    - Scalability
    - Security
    - Supportability
    - Usability
    - Localization
- Reporting Requirements
    - Description
    - Header & Footer
    - Layout
    - Security & Access
    - Report Logic
- Supplemental Info
    - Glossary
    - Appendix
    - Approvers & Signoff
    - References

5. SRS Conventions/Best Practices
- Create a separate BRD
- Involve Key Stakeholders
- Enable Manegability
- Use Checklists
- Use Visuals
    - Context Diagrams
    - Sequence Diagrams
    - Functional Decomposition
    - Usecase Diagrams
    - As-Is/To-Be Process Models
    - User Stories
    - Mind Map
- Be clear
